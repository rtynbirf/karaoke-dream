# Дорожная карта

Логика развития — та же, что и у «Зелёного коридора»: каждый шаг снижает цену следующего. Фазы выстроены так, чтобы каждая давала пользователю самостоятельную ценность, а не «недостроенный мост».

## Фаза 0 — Прототип (готово, v0.1.0)

| Результат | Статус |
|---|---|
| Браузерное караоке: демо-сцена, синтез минуса в браузере | готово |
| Гид-мелодия с живой громкостью | готово |
| Pitch-детектор YIN, оценка (точность/ритм/стабильность), режимы «Дружелюбный»/«Жюри» | готово |
| «Зелёный коридор»: адаптивная транспозиция detune-ом | готово |
| Enhanced LRC: подсветка слов, парсер/сериализатор | готово |
| Свой трек + LRC, минус-вокал (центр-канал), свободный режим | готово |
| Вечеринка: очередь, лидерборд, большой экран | готово |
| CI (Node 18/20/22), тесты чистой логики, smoke-импорт | готово |

## Фаза 1 — «Сцена» (оценка: 2–3 недели)

Цель: от «прототипа, в который влюбляются» к «продукту, который рекомендуют».

- Запись выступления: `MediaRecorder` (микрофон + минус в один файл), маркеры лучших моментов по пикам оценки, плеер реплея.
- Автокалибровка задержки: клик-тест «услышь и пой» вместо ручного слайдера (сейчас 0–300 мс).
- PWA-каркас: манифест, service worker, иконки; оффлайн после первого визита.
- Микро-обучение: подсказки «дотяни ноту» / «вступай раньше» по статистике слабых мест.
- Критерий приёмки: первый спектакль < 60 секунд от открытия страницы; запись сохраняется и проигрывается.

## Фаза 2 — «Стемы» (оценка: 4–6 недель)

Цель: настоящий AI-минус из любого трека и эталонная мелодия для полной оценки.

- Разделение стемов: Demucs v4 / MDX-ONNX через ONNX Runtime Web (WASM/WebGPU), с серверным фолбэком для слабых устройств.
- Автотранскрипция мелодии (melodia-подход / CREPE) → MIDI-эталон любого трека → полная оценка (точность питча) для своих песен.
- Смена тональности/темпа раздельно (WSOLA/phase-vocoder поверх стемов).
- Библиотека сессий: сохранение сетапа песни (минус, MIDI, LRC) в IndexedDB.
- Критерий приёмки: для случайного поп-трека из 10 песен ≥ 8 получают чистый минус и оценку без ручной правки.

## Фаза 3 — «Вечеринка 2.0» (оценка: 4 недели)

Цель: караоке как социальная сцена, а не соло-практика.

- Сетевые комнаты по коду (WebRTC mesh / SFU-малого размера): общая очередь, синхронный большой экран.
- Телефон-пульт: QR-код, телефон — пульт и микрофон, телевизор — сцена.
- Баттлы: дуэли 1×1 и 2×2, голосование зрителей, сезонные лидерборды.
- Хайлайты вечеринки: авто-нарезка лучших строк всех участников.

## Фаза 4 — «Коридор 2.0» (оценка: 3 недели)

Цель: персональная среда обучения — сингулярный дифференциатор проекта.

- Профиль голоса: диапазон, тесситура, типичные ошибки — измеряются и хранятся локально.
- Упражнения-распевки с кривой прогресса; подбор песен под диапазон из библиотеки.
- Коридор по осям: тональность + темп + плотность гид-вокала (частичный гид → безгидрoвый режим).
- Экспорт прогресса (JSON/CSV).

## Фаза 5 — Релиз

- Публикация на GitHub Pages + домен; Lighthouse ≥ 95 по всем осям.
- Метрики (локальные, приватные): DAU-оценка по локальным сессиям, воронка «открыл → спел первую строку → спел песню до конца».
- Чек-лист доступности (WCAG AA), локализации (RU/EN).

## Зависимости и риски

| Фаза | Зависит от | Главный риск | Мера |
|---|---|---|---|
| 1 | — | Латентность записи/плеера | ранние замеры на устройствах-аутсайдерах |
| 2 | — | Вес модели стемов в браузере | квантование, WebGPU-фолбэк, серверная опция |
| 3 | 1 | NAT/ TURN-инфраструктура | минимум TURN, максимально mesh |
| 4 | 2 | Качество автотранскрипции | ручная правка MIDI в редакторе сессий |

## KPI по фазам

- Ф1: время до первого спетого куплета < 60 с; D7-возврат ≥ 25% (локальная оценка).
- Ф2: доля треков с успешным автоплюсом ≥ 80%; оценка питча доступна без ручных файлов.
- Ф3: ≥ 2 участников в комнате в 60% сессий; очередь используется в каждой вечеринке.
- Ф4: медианный сдвиг коридора за месяц −1 пт и менее (певцы растут, среда возвращается).
