# Техническое задание: KARAOKE DREAM 2.0 (MVP-прототип)

Версия: 1.0 · Дата: 2026-10-28 · Статус: реализовано в прототипе v0.1.0 (отклонения помечены)

## 1. Общие сведения

- Название проекта: KARAOKE DREAM 2.0 («Неоновый вектор»).
- Тип: клиентское браузерное приложение (SPA, zero-dependency, без сборки).
- Платформы: настольные и мобильные браузеры с WebAudio и getUserMedia (Chrome, Firefox, Safari, Edge последних версий).
- Ограничение доступа: микрофон требует HTTPS или localhost.

## 2. Цели и метрики успеха

| ID | Метрика | Целевое значение |
|---|---|---|
| M1 | Время от открытия страницы до начала первой песни | ≤ 60 с |
| M2 | Задержка контура оценки (голос → кадр) | ≤ 120 мс при ручной компенсации |
| M3 | Плавность UI во время исполнения | ≥ 55 FPS на ноутбуке 2018 года |
| M4 | Точность YIN на чистом вокале (ручные замеры) | отклонение ≤ 3 полутона-доли от эталонной ноты |
| M5 | Приватность | 0 сетевых запросов во время сессии |

## 3. Пользователи и сценарии

Персона 1 — «Домашний певец»: хочет петь любимое без страха оценки. Сценарий: открыл → демо → коридор подстроился → получил 61 → спел ещё круг на 74.

Персона 2 — «Ведущий вечеринки»: собирает гостей, ведёт очередь. Сценарий: наполнил очередь именами → каждый поёт демо → лидерборд на большом экране.

Персона 3 — «Музыкант-экспериментатор»: грузит свой трек и LRC, убирает вокал, поёт со своей лирикой. Сценарий: загрузил mp3 → включил минус → вставил LRC → пел.

User stories: US-1 спеть демо без установки; US-2 видеть свою ноту относительно эталона в реальном времени; US-3 получить оценку строки сразу после её конца; US-4 чувствовать, что песня идёт навстречу (коридор); US-5 вести очередь на вечеринке; US-6 петь свой трек со своей лирикой; US-7 вернуться и увидеть свой рекорд.

## 6. Критерии приёмки

- AC-1: открытие демо → через ≤ 60 с слышна сцена и видно слово-подсветку (M1).
- AC-2: при пении в ноту кривая на питч-трейле визуально совпадает с плашками ноты.
- AC-3: после конца каждой строки счёт строки обновляется в HUD.
- AC-4: три строки с баллом < 55 → коридор сдвинулся на −1 пт; чип «коридор» обновился; ноты на трейле и эталон оценки сдвинулись согласованно.
- AC-5: после серии строк > 82 коридор возвращается к 0; темп песни неизменен на слух.
- AC-6: смена «Жюри»↔«Дружелюбный» меняет итоговые баллы одной записи голоса предсказуемо (допуски ×1.6).
- AC-7: mp3 без LRC: оценка не показывается, активность видна, минус-вокал работает.
- AC-8: очередь из 3 имён: каждый поёт, лидерборд заполняется, порядок сохраняется между перезагрузками.
- AC-9: тесты и smoke зелёные; CI проходит на матрице Node.
- AC-10: в Network-вкладке нет запросов во время исполнения (после загрузки страницы).

## 7. Риски и меры

| ID | Риск | Вероятность | Мера |
|---|---|---|---|
| R1 | Разный аудио-выход/вход latency у устройств | высокая | ручная компенсация (FR-10) + автокалибровка в фазе 1 |
| R2 | YIN ошибается на октаву у низких голосов | средняя | медианный фильтр кадров; диапазон 70–1100 Гц; тюнинг порога |
| R3 | detune не поддержан старым браузером | низкая | фолбэк playbackRate (меняет темп) с предупреждением в docs |
| R4 | Центр-канал не убирает вокал в широких сведениях | высокая (свойство метода) | честная пометка в UI; ML-стемы в фазе 2 |
| R5 | iOS Safari ограничивает AudioContext до жеста | средняя | контекст создаётся по клику «На сцену» (resume в ensureCtx) |
| R6 | Громкий гид мешает оценке тембра | средняя | отдельная громкость гид-вокала (FR-23) |
