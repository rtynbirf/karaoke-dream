# Вклад в KARAOKE DREAM

Спасибо, что хотите усилить вектор проекта. Ниже — канон, по которому живёт эта репа.

## Быстрый старт разработки

```bash
git clone https://github.com/rtynbirf/karaoke-dream.git
cd karaoke-dream
npm run dev      # локальный сервер на http://localhost:5173 (микрофон требует localhost/HTTPS)
npm test         # тесты чистой логики (node:test, без зависимостей)
npm run smoke    # smoke-импорт всех ES-модулей под Node
```

## Правила земли

1. **Zero-dependency в рантайме.** Никаких `npm install` для работы приложения. Новые библиотеки — только по архитектурному решению (см. `docs/03-architecture.md`, ADR).
2. **Чистая логика отделена от ввода-вывода.** Всё, что можно тестировать без браузера (парсеры, scoring, политика коридора, композитор), живёт в модулях без обращений к `document`/`AudioContext` на верхнем уровне и покрывается тестами в `tests/`.
3. **ES-модули с расширением `.js` в импортах** — проект работает и без сборщика, и под Node.
4. **Пользовательский текст не попадает в `innerHTML`** — только `textContent`/`createElement` (см. `SECURITY.md`).
5. **Conventional Commits**: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`. Тема на английском, тело — по желанию на русском.
6. Одна фича — один PR. PR должен держать зелёными `npm test` и `npm run smoke`.

## Структура, которую нельзя ломать молча

- `src/js/lyrics`, `src/js/scoring`, `src/js/songs` — чистая логика (тестируемая).
- `src/js/audio` — WebAudio: движок, pitch, синтезатор.
- `src/js/ui` — DOM/canvas (не тестируется в Node, только smoke).
- `docs/` — канон проекта: ТЗ, архитектура, roadmap. Меняешь поведение — обнови соответствующий документ в том же PR.
